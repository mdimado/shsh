
Experiment 01 – Nmap and Wireshark
---------------------------------
Aim:
To use Nmap for scanning hosts and identifying services, and analyze the scan traffic in Wireshark to understand TCP/UDP/ICMP behavior and OS detection.

Description:
Nmap is a tool for scanning hosts, services, and operating systems. Wireshark captures the packets generated by these scans. Together, they help us see how scanning techniques work internally.

Procedure:
1. Host Discovery (Ping Sweep)
   nmap -sn 192.168.1.0/24
   Wireshark filter: icmp

2. SYN Scan (Stealth Scan)
   nmap -sS <target_ip>
   Wireshark filters:
   - tcp.flags.syn == 1 && tcp.flags.ack == 0 (SYN)
   - tcp.flags.syn == 1 && tcp.flags.ack == 1 (SYN-ACK)
   - tcp.flags.reset == 1 (RST for closed ports)

3. Service and Version Detection
   nmap -sS -sV <target_ip>

4. UDP Scan
   nmap -sU -p 53,123,161 <target_ip>
   Wireshark filter: udp

5. Aggressive Scan
   nmap -A <target_ip>

6. All Port Scan
   nmap -p- <target_ip>

7. OS Detection
   nmap -O <target_ip>

Conclusion:
Nmap scans reveal open ports, services, and OS details. Wireshark confirms packet behavior (ICMP, SYN/ACK, UDP). This shows how attackers scan systems and how defenders can detect it.


Experiment 02 – Firewall Rules
------------------------------
Aim:
To configure firewall rules and test them using Ncat and Nmap.

Description:
Firewalls control access to network ports. We allow one port and block another, then verify with Nmap scans.

Procedure (Windows PowerShell as Admin):
1. Allow Rule for Port 5555
   New-NetFirewallRule -DisplayName "Allow TCP 5555" -Direction Inbound -Protocol TCP -LocalPort 5555 -Action Allow

2. Block Rule for Port 4444
   New-NetFirewallRule -DisplayName "Block TCP 4444" -Direction Inbound -Protocol TCP -LocalPort 4444 -Action Block

3. Start Listener on Allowed Port
   ncat -lvp 5555

4. Scan with Nmap
   nmap -p 5555,4444 127.0.0.1

Expected Result:
- Port 5555 → Open
- Port 4444 → Closed/Filtered

Conclusion:
Firewall rules successfully allowed port 5555 and blocked port 4444. Shows how firewalls enforce network security.


Experiment 03 – Web App Security Testing
----------------------------------------
Aim:
To create a web app, test it with OWASP ZAP/Burp, and identify vulnerabilities like SQL Injection, XSS, or weak authentication.

Description:
Web apps are vulnerable to attacks if inputs are not validated. Tools like Burp/ZAP can find these issues.

Procedure:
1. Build a Simple Web App (Flask vulnerable query)
   @app.route("/login")
   def login():
       user = request.args.get("user")
       pwd = request.args.get("pwd")
       query = f"SELECT * FROM users WHERE name='{user}' AND password='{pwd}'"
       result = db.execute(query)   # Vulnerable to SQLi

2. Setup Burp Suite
   - Open Burp
   - Set browser proxy to Burp

3. Scan the Web App
   - Look for reflected XSS, SQL injection, missing headers

4. Fix Vulnerabilities (Secure code)
   query = "SELECT * FROM users WHERE name=%s AND password=%s"
   cursor.execute(query, (user, pwd))

Conclusion:
Initial scan found SQL injection and XSS. After using prepared statements and validation, app became secure. Demonstrates importance of testing and secure coding.


Experiment 07 – OpenSSL Encryption and SSL/TLS
----------------------------------------------
Aim:
To use OpenSSL for file encryption/decryption and configure SSL/TLS on a web server.

Description:
OpenSSL provides encryption and certificate generation. Encryption protects files, while SSL/TLS secures websites.

Procedure:

Part A – File Encryption/Decryption
1. Create plaintext:
   echo "This is a secret message" > secret.txt

2. Encrypt file:
   openssl enc -aes-256-cbc -pbkdf2 -iter 100000 -salt -in secret.txt -out secret.enc

3. Decrypt file:
   openssl enc -d -aes-256-cbc -pbkdf2 -iter 100000 -in secret.enc -out secret_decrypted.txt

4. Compare files:
   fc secret.txt secret_decrypted.txt

Part B – SSL/TLS Setup
1. Generate key + certificate:
   openssl req -x509 -newkey rsa:2048 -nodes -keyout key.pem -out cert.pem -days 365

2. Run HTTPS server (Python):
   from http.server import HTTPServer, SimpleHTTPRequestHandler
   import ssl
   httpd = HTTPServer(('localhost', 4443), SimpleHTTPRequestHandler)
   httpd.socket = ssl.wrap_socket(httpd.socket, keyfile="key.pem", certfile="cert.pem", server_side=True)
   httpd.serve_forever()

Conclusion:
Files were encrypted/decrypted successfully. HTTPS server worked with self-signed cert. Shows how encryption and SSL protect confidentiality and integrity.


Experiment 09 – Database Security and SQL Injection
---------------------------------------------------
Aim:
To secure a database and test SQL injection attacks using SQLMap.

Description:
Databases are vulnerable when queries use user input directly. SQLMap can exploit this. Secure coding prevents it.

Procedure:
1. Create Database + Table (PostgreSQL)
   CREATE DATABASE testdb;
   \c testdb;
   CREATE TABLE users(id SERIAL, name TEXT, password TEXT);
   INSERT INTO users(name, password) VALUES ('admin', 'admin123');

2. Vulnerable Flask App
   @app.route("/login")
   def login():
       user = request.args.get("user")
       query = "SELECT * FROM users WHERE name='" + user + "';"
       result = db.execute(query)   # Vulnerable

3. Run SQLMap
   sqlmap -u "http://127.0.0.1:5000/login?user=admin"

4. Fix with Parameterized Queries
   query = "SELECT * FROM users WHERE name=%s;"
   cursor.execute(query, (user,))

5. Re-test with SQLMap → Injection fails.

Conclusion:
SQLMap extracted data from the vulnerable app, but after secure coding (parameterized queries, validation), SQL injection was prevented. Shows how secure coding defends databases.
